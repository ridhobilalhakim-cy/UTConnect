## No fabricated lockfile

`package-lock.json` is intentionally absent. It must be generated by npm in a network-enabled environment so npm records authentic package versions, resolved tarball URLs, and integrity hashes.

## Remote build bootstrap

The repository now includes `.github/workflows/verify-build.yml`:

1. Push the source to a GitHub repository on `main` or `master`.
2. GitHub Actions installs dependencies. If `package-lock.json` is missing, it generates one in the runner first.
3. The workflow runs `npm ci`, `npm run check`, and `npm run build`.
4. A successful workflow uploads `dist/` and `package-lock.json` as a 14-day artifact.
5. Download the lockfile from the artifact, commit it to the repository, and rerun CI. The second run must use `npm ci` against the committed lockfile.
6. Only after that succeeds, connect the repository to Netlify and use `dist` as the publish directory.

The workflow has been written but has **not** been executed; it needs the source pushed to GitHub first.

## Scope boundary

This gate verifies code structure and prepares the remote build path. It does not test browser rendering, Supabase login/Google OAuth, registration, session restoration, or any live multi-user dashboard feature. The dashboard remains a demo UI until feature integrations are implemented and tested separately.
